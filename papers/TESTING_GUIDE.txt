================================================================
 LSPU SCHOLARHUB - STEP BY STEP TESTING GUIDE
 Test every role. Follow the order: Guest -> Student -> Staff
 -> Admin -> Super Admin. Use a second browser or incognito
 window to test two roles at the same time.
================================================================


=====================================================
 1. GUEST (not logged in)
=====================================================

 View landing page
   1. Open the site URL while logged out.
   2. Check: header shows Home, Scholarships, AI Assistant,
      Login, Register.
   3. Check: NO "Contact" link in the header.
   4. Check: footer shows contact info (left side),
      Quick Links, and LSPU ScholarHub branding.

 Browse scholarships
   1. Click "Scholarships" on the landing page.
   2. Check: only OPEN, non-hidden programs show.
   3. Check: campus badges show (All Campuses or
      SC/SN/SBC/LB).
   4. Check: NO "Browse" button on scholarship cards
      (guests must register first).
   5. Open one program's details page.
   6. Check: Apply is NOT offered to guests (login
      prompt instead).

 Test the AI Assistant
   1. Click "AI Assistant".
   2. Ask: "What scholarships are open?"
   3. Check: it lists the same open programs as the page,
      and NEVER mentions a hidden program.
   4. Check: AI does NOT reveal private/internal program
      details to guests.

 Try to register (document-verified)
   1. Click Register. Fill the form:
      - First Name, Last Name, Middle Name (optional)
      - Email, Phone (11 digits)
      - Gender, Town, Province
      - Course/Program (from dropdown)
      - Year Level (1st-5th Year, Irregular, Graduate)
      - Birthday (calendar picker, mm/dd/yyyy)
      - Campus (from dropdown)
      - Student ID (format: XXXX-XXXX)
   2. Existing Scholar Declaration:
      - Check "I am already a scholar in LSPU"
      - Enter the scholarship program name
      - This is ONLY for students who don't have an
        account yet but are already scholars
   3. Upload documents:
      - COR as PDF (required for all year levels)
      - Copy of Grades as PDF (required for 2nd-5th year)
      - Images are REJECTED (PDF only)
      - Files over 5MB are REJECTED
   4. Test document verification:
      - Select year level DIFFERENT from COR -> BLOCKED
      - Enter birthday DIFFERENT from documents -> BLOCKED
      - Select campus DIFFERENT from documents -> BLOCKED
      - Enter student ID DIFFERENT from documents -> BLOCKED
   5. Enter everything correctly -> OTP is sent to email.
   6. Enter the OTP -> account is created and verified.
   7. Check: welcome email with temporary password arrives.

 Test login and password
   1. Log in with the temporary password.
   2. Check: system asks you to set a new password.
   3. Try a weak password (e.g. "abc12345") -> must be
      rejected (needs 8+ chars with upper, lower, number).
   4. Set a valid password, log out, log back in.


=====================================================
 2. STUDENT
=====================================================

 Dashboard
   1. Log in as a student.
   2. Check: header shows Dashboard, Scholarships, My
      Applications, My Scholarship (only if approved),
      Notifications, AI Assistant.
   3. Check: stat cards are centered and relevant:
      - Total Applications
      - Approved
      - Pending/Under Review (merged status)
      - Total Awards
   4. Check: GWA card shows current GWA (no "outdated"
      label).
   5. Check: document reminder section (not "Grades Need
      Updating" - just a reminder to upload latest COR
      and grades).

 Browse and apply
   1. Open Scholarships.
   2. Check: only own-campus + university-wide programs
      show. Hidden programs must NOT appear.
   3. Open a program, click Apply.
   4. Check: form is PRE-FILLED (name, ID, course, year
      level, GWA, units, birthday) - only custom
      questions to answer.
   5. Check: NO essay and NO document upload needed when
      applying.
   6. Check: "Upload Grades" option is NOT present on
      the apply page.
   7. Submit. Check the success message.

 One-public-program rule (per academic period)
   1. Apply to a second PUBLIC program while one public
      application is pending/approved in the SAME period
      -> must be blocked.
   2. Apply to a PRIVATE program -> must be ALLOWED even
      with a public one.
   3. Apply to a PUBLIC program in a NEW period after
      being approved in a previous period -> must be
      ALLOWED (renewal-by-reapplication works).

 My Applications
   1. Open My Applications.
   2. Check: stat cards are centered (total,
      pending/under review, approved).
   3. Check: "Pending" and "Under Review" are merged
      into one status.
   4. Check: status shows Pending, then
      Approved/Rejected.
   5. Check: approved/rejected applications are moved
      to a separate section (not mixed with pending).
   6. Click Edit on a pending application, change an
      answer, save.
   7. Check: button says "Resubmit" not "Submit".
   8. Click the Back button after editing -> must NOT
      show error 500.
   9. Withdraw a pending application -> confirmation
      dialog appears, status becomes Withdrawn.

 Notifications
   1. Open Notifications.
   2. Check: application received/status emails and SMS
      also arrived (check email inbox and phone).

 My Documents (replace COR/Grades)
   1. Open My Documents.
   2. Replace the Copy of Grades with a new PDF.
   3. Check: PDF-only rule enforced.
   4. Check: 5MB file size limit enforced.
   5. Check: wrong-document-type swap is blocked
      (uploading COR where grades belong -> blocked).
   6. Check: after upload, GWA and units update
      automatically.
   7. Check: if the new document shows a different
      campus, the account campus updates to match.

 My Scholarship (approved students only)
   1. Log in as a student with an approved scholarship.
   2. Check: My Scholarship appears in the header.
   3. Check: ALL approved programs are listed (student
      can hold one public + private programs).
   4. Check: program details, benefits, and batch info
      show.
   5. Download the Monitoring & Evaluation form.
   6. Upload a photo/PDF of the filled M&E form
      (max 5MB).
   7. Check: green banner with View Submission and
      Replace.
   8. Check: deadline banner color (blue/yellow/red).

 My Profile
   1. Open My Profile.
   2. Check: campus shows in Profile Information.
   3. Check: there is NO "Update Your GWA" card.
   4. Check: Application Summary section is removed
      (redundant with dashboard).
   5. Check: "I am already a scholar in LSPU"
      declaration is present.
   6. Edit phone number and address, save.
   7. Change password (old password required).

 AI Assistant as student
   1. Open AI Assistant.
   2. Ask "What scholarships can I apply to?"
   3. Check: reply is personalized and never leaks
      hidden or other-campus programs.


=====================================================
 3. STAFF (campus-scoped)
=====================================================

 Log in as staff
   1. Log in with a staff account.
   2. Check: header shows Dashboard, Scholarships,
      Applications, Students, Batches, Monitoring,
      Reports, Announcements, Profile.
   3. Check: campus badge shows the staff's campus.

 Review applications
   1. Open Applications (Review queue).
   2. Check: only own-campus applications show.
   3. Open one application: check the pre-filled
      profile, custom answers, GWA.
   4. Move one to "Under Review".
   5. Approve one (with notes) -> student gets in-app
      + email + SMS.
   6. Reject one (with reason) -> same notifications.

 Create a scholarship program
   1. Scholarships -> Create.
   2. Fill: title, description, award amount (try a
      negative number -> must be blocked, 0 minimum),
      slots (try negative -> blocked, 0 minimum),
      eligibility, benefits, funding type
      (public/private), scope (campus or university-wide),
      and custom form fields.
   3. Choose "announce this program" -> check students
      get the announcement (email/SMS/in-app).
   4. Create a HIDDEN program with specific student IDs
      allowed -> check only those students see it.
   5. Check: announcement always has SMS and Email
      options available.

 Batch the approved scholars
   1. Batches -> Create batch.
   2. Check: the batch is named after the scholarship
      program and created in ONE action.
   3. Open the batch: check every scholar's info is
      complete and viewable.
   4. Export the batch to Excel -> open the file and
      verify.

 Monitoring and tracking
   1. Open Monitoring.
   2. Check: scholars table shows M&E Form column.
   3. Check: "Overdue" badge (red) for scholars who
      missed the deadline.
   4. Check: M&E Overdue stat card shows the count.
   5. Click a "Submitted" badge -> the student's
      uploaded M&E file opens in a new tab.
   6. Update a scholar's GWA / status.

 Reports
   1. Open Reports.
   2. Check: charts render and RESIZE when the window
      is resized.
   3. Check: numbers are campus-scoped (only own
      campus data).
   4. Export the report -> file downloads correctly.

 Students directory
   1. Open Students.
   2. Check: only own-campus students.
   3. Check: "Existing scholar" badge shows for
      students who declared it.
   4. Check: "Scholar Declaration" filter works
      (All / Declared / No declaration).
   5. Open one student: view their documents (opens in
      tab, not forced download).
   6. Check: "Add to Program" button exists for
      existing scholars.

 Announcements
   1. Announcements -> compose.
   2. Check: SMS and Email options are ALWAYS available.
   3. Check: Attachments field is present (optional).
   4. Attach a file (PDF/Word/Excel/image, max 3 files,
      5MB each).
   5. Send -> students receive email with attachment.
   6. Try attaching a .exe file -> must be rejected.


=====================================================
 4. ADMIN (campus-scoped, everything staff can do plus)
=====================================================

 Everything in the Staff section above, plus:

 Manage users
   1. Users -> see all users with campus column.
   2. Check: campus filter works.
   3. Create a Staff account: fill all fields INCLUDING
      campus -> account is created and scoped.
   4. Create an Admin account the same way.
   5. Change a user's role with the role dropdown ->
      confirmation appears, role updates.
   6. Try to change YOUR OWN role -> must be blocked.
   7. Disable a user, then try to log in as that user
      -> login is blocked. Re-enable.
   8. Delete a test staff account -> confirmation,
      removed. (Cannot delete yourself or last admin.)

 Edit a user
   1. Click Edit on a student: update name, phone,
      student ID, course, year level (check 1st-5th
      Year, Irregular, Graduate in dropdown), address.
   2. Reset a password (min 8 chars, policy enforced).
   3. Save -> changes reflected.

 Student directory and files
   1. Students -> Directory.
   2. Open a student's profile.
   3. View their COR and Grades files -> open in a new
      tab (viewable, not auto-download).
   4. Check: "Existing scholar" badge and "Add to
      Program" button.

 Bulk import
   1. Students -> Bulk Import.
   2. Download the template, fill a row, import.
   3. Check: the student appears in the users list.

 Announcements
   1. Announcements -> compose.
   2. Check: SMS and Email options are ALWAYS available.
   3. Check: Attachments field is present (optional).
   4. Send with and without attachments.

 Periods (Super Admin ONLY)
   1. Log in as campus admin -> check: Periods link is
      NOT in the navbar.
   2. Log in as super admin -> check: Periods link IS
      in the navbar.
   3. Open Periods (Academic Periods).
   4. Create a new academic period (e.g. '1st Semester
      2026-2027').
   5. Set a period as current -> old period is unset.
   6. Set the M&E form deadline for the current
      semester -> students see the deadline banner.
   7. Try accessing /admin/settings as campus admin ->
      must redirect with error message.

 Reports and audit
   1. Reports -> charts + export work.
   2. Check: numbers are campus-scoped.
   3. Audit Log -> shows who did what; export works.


=====================================================
 5. SUPER ADMIN (all campuses)
=====================================================

 Campus switcher
   1. Log in as superadmin.
   2. Check: full admin navbar (Dashboard, Scholarships,
      Applications, Students, Batches, Monitoring,
      Notifications, Reports, Periods, Profile, Users)
      AND the "All Campuses" selector at the top right.
   3. Switch to "Santa Cruz" -> ALL pages filter to
      that campus (dashboard, scholarships, applications,
      monitoring, batches, students, reports).
   4. Switch to "Siniloan" -> data changes accordingly
      (may be empty if no data).
   5. Switch back to "All Campuses" -> everything shows.

 Campus-scoped scholarship management
   1. Scholarships: check the Campus column (All for
      university-wide, SC/SN/SBC/LB otherwise).
   2. Create a UNIVERSITY-WIDE program -> check students
      from at least two campuses can see it.
   3. Create a CAMPUS-SPECIFIC program -> check ONLY
      that campus's students see it.
   4. Edit/delete a program -> must be blocked for
      cross-campus programs.
   5. Toggle visibility -> works only for own campus or
      university-wide programs.

 Manage across campuses
   1. Users: filter by each campus; create staff/admin
      for ANY campus.
   2. Batches: check batches from all campuses are
      visible; open one; export it.

 Monitoring, reports, audit
   1. Monitoring -> scholars from all campuses, M&E
      column works, overdue badges show.
   2. Reports -> numbers make sense per campus.
   3. Audit Log -> super admin actions are logged too.

 Period management
   1. Open Periods -> create a new period.
   2. Set it as current -> old period is unset.
   3. Set the M&E deadline for the current period.
   4. Try accessing /admin/settings as campus admin ->
      must redirect with error.

 Role management safety
   1. Demote an admin to staff while a super admin
      exists -> should be ALLOWED.
   2. Promote a staff to Admin for their campus.
   3. Try to change your own role -> must be blocked.
